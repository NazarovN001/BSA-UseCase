# Use Case Diagrams — Моделирование вариантов использования

## О проекте
Учебный проект Школы 21 (индивидуально).  
Разработал комплекс диаграмм Use Case для документирования функциональных требований и сценариев взаимодействия пользователей с системой.

## Моя роль
- Выявил и описал ключевых акторов системы
- Спроектировал основные и альтернативные сценарии использования
- Создал визуальные UML Use Case диаграммы
- Подготовил спецификации вариантов использования для команды разработки

## Выполненные задачи

### Задание 1: Идентификация акторов
- Определил первичных и вторичных акторов системы
- Описал цели и ожидания каждого актора
- Выявил границы системы и внешние взаимодействия

### Задание 2: Проектирование Use Case
- Сформулировал основные сценарии (Main Flow)
- Описал альтернативные сценарии и обработку ошибок (Alternative Flows)
- Определил предусловия и постусловия для каждого сценария

### Задание 3: Визуальное моделирование (UML)
- Построил диаграмму вариантов использования в нотации UML 2.5
- Отобразил отношения Include и Extend между сценариями
- Согласовал диаграмму с логикой бизнес-процессов

### Задание 4: Спецификация требований
- Детализировал каждый Use Case в текстовом формате
- Связал сценарии с бизнес-требованиями
- Подготовил артефакты для передачи в разработку и тестирование

## Результаты
- ✅ Полная карта вариантов использования системы
- ✅ UML-диаграммы, понятные как бизнесу, так и разработчикам
- ✅ Детальные спецификации сценариев (Main/Alternative flows)
- ✅ Выявленные краевые случаи (edge cases) и способы их обработки

## Инструменты
- Draw.io / Lucidchart / PlantUML
- UML 2.5 (Use Case Diagram)
- Текстовые процессоры для спецификаций

## Структура проекта
- `src/use-case-diagram/` — визуальные диаграммы
- `src/specifications/` — текстовые описания сценариев
- `src/actors/` — описание ролей и акторов
